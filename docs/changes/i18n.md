Style rules: keep `{placeholders}` and plural keys exactly; keep the English
typographic quotes “…” and the ellipsis character `…`; query syntax
(`is:open`, `@source:user`, `due:overdue`) and file names (`settings.json`) are
never translated; product and brand names (Luau, Jira, VS Code, Ollama…) stay as-is.

## Logic

### `pnpm i18n <locale>`
- **en**: unchanged behaviour: every static key used in `src/` (`t('…')`,
  command `title: '…'`) must exist in `en.ts` + `parts/*.en.ts`.
- **es / pt**: the same check resolved **in that locale only** (no English
  fallback), plus a structural walk of the merged English dictionary:
  - missing key or wrong shape (text vs. object/plural) → **error**;
  - a placeholder not present in the English string (would render literally) → **error**;
  - a dropped placeholder, or a key that doesn't exist in English → **warning**;
  - plural objects must contain every English form; extra CLDR forms (`many`) are allowed.
- Exit code 1 on any error, so CI blocks merges that add English strings without translations.

### `index.svelte.ts` fixes
1. `relTime()` threw `RangeError` from `Intl.RelativeTimeFormat.format(NaN)` for a
   missing/invalid timestamp (e.g. a node without `mtime`), breaking the render. It now returns `''`.
2. `fmtDate()` showed “Invalid Date”; it now returns the original string (or `''`).
3. `setLocale()` crashed (`loaders[locale] is not a function`) if `settings.json`
   held an unsupported value such as `"fr"` or `"es-CL"`. Values are normalized
   with `normalizeLocale()` (`es-CL` → `es`, unknown → `en`).
4. `detectLocale()` only looked at `navigator.language`; it now walks
   `navigator.languages` and picks the first supported language (a user with
   `de-DE, es-CL` gets Spanish instead of English).

Not changed (checked, correct): per-key English fallback in `t()`, plural
selection with `Intl.PluralRules(locale)` (note: CLDR `pt` treats 0 as `one`),
and relative/absolute date formatting with the active locale (`pt` resolves to pt-BR in Intl).

## Technical decisions
- **lane = lista** instead of columna/coluna — see glossary.
- Template lane names use words the activity-summary stage dictionary (SPEC §12.3)
  recognises in Spanish (*Por hacer*, *En curso*, *Hecho*, *En revisión*).
- Translations live in plain objects without a type tie to `en.ts`, so a
  missing key never breaks the build; completeness is enforced by the check script instead.

## Risks / assumptions
- Parallel feature branches must ship `<feature>.es.ts` and `<feature>.pt.ts`;
  after merging, `pnpm i18n es|pt` (now in CI) will list anything missing.
- Some strings are long in Spanish/Portuguese (≈ +20–30 %); tight UI spots
  (segmented controls, tab titles) should be reviewed visually.
- Translations were written by hand, not reviewed by a native Portuguese speaker.

## Tests

- Negative test of the checker with a temporary part file (missing key, unknown

- `npx vitest run` — all tests pass, including new `src/lib/i18n/i18n.test.ts`
  (locale normalization/detection, es/pt plurals and placeholders, invalid dates, relative time in es/pt).
- `pnpm check` — 0 errors, 0 warnings.
